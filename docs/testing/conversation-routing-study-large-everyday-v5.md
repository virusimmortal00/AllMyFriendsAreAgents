# Everyday conversation lever study (schema 5)

Jev is the room's advisory reply-routing classifier; see [issue #232](https://github.com/virusimmortal00/AllMyFriendsAreAgents/issues/232) and the [live canary guide](conversation-routing-live-canary.md) for the existing study context.

The [closed plan](conversation-routing-study-large-everyday-v5.json) contains 36 matched pairs, or 72 isolated room cases. It replaces the garden examples for a prospective study while preserving the earlier plan and its historical results. Each pair repeats the same scripted human turns, roster, energy, room identity, terminal instruction, and global actor model. The only treatment difference is one of three factors: Jev question (`current-v1` versus `lean-v1`), optional gate (`current-v1` versus `relevance-v1`, both with the relevance Jev question), or agent base prompt (`current-v1` versus `social-v1`). Each factor has 12 pairs, balanced between six everyday-chat and six practical-work profiles, with three AB and three BA orderings within each factor and theme. The frozen seed places agent-prompt/multi-address/everyday, Jev/direct/practical, and gate/broadcast/everyday in the first three-pair inspection batch.

The 36 closed conversation profiles span all seven routing dynamics, one through three roster agents, and one through three human messages. Each prompt supplies enough context to answer without assuming unseen prior discussion. Named addresses use the neutral room cards Riley, Jordan, and Casey; the quoted-name profiles contain those names only inside quoted notes, so their expected direct-target list is empty. The gate pairs include an optional participant on at least one turn. One handoff profile asks Riley to solicit Jordan's view while the human directly addresses only Riley, allowing the live run to observe an agent-to-agent invitation. A silent agent is a valid conversational outcome, especially on casual turns. Distinct profile IDs and text-bound digests prevent one pair's prompt from silently standing in for another.

The plan pins `room-v1` and `contribution-first-v1` on both arms. The actor model is supplied once by the runner and must remain the same for all 72 cases. The closed schema rejects missing or duplicated profiles, unknown fields or profile IDs, factor drift, rosters wider than three, and addresses to absent agents. The source-text digest changes if any visible scenario text changes. Existing schema 1–4 plans and their digests remain unchanged.

This file describes a provider-free plan. A dry-run and the separate live runner integration must be audited before any paid execution. Live results and raw conversations belong in private local output, with human grading generated from the completed matched manifests.
